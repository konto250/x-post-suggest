# ことばのつづき — x-post-suggest

Xのポストから返信案を考える、自分専用のローカルWebアプリです。本文、本文中のリンク先、ハッシュタグ、同じ相手への過去の返信をOpenAI APIに渡して3案を生成します。

## 起動

Node.js 22.9以降を使用してください。

```powershell
npm install
npm run dev
```

ブラウザーで http://localhost:4317 を開きます。保存先を統一するため、以後もこのURLを使用してください（127.0.0.1や異なるポートは別の保存先になります）。サーバーは127.0.0.1でのみ待ち受けます。

APIキーとログイン用パスワードはサーバー側の環境変数に設定します。初回は `.env.example` を `.env.local` にコピーし、`OPENAI_API_KEY` を設定して `npm run setup:access` を実行してください。既存の適切な `APP_ACCESS_TOKEN` は維持し、未設定・不正なら32バイトの乱数から43文字の値を生成します。値はコマンド出力に表示しません。ログインには `.env.local` の `APP_ACCESS_TOKEN` を使います。キーとモデル・パスワードは次回の要求時に再読み込みします。ポート変更は再起動が必要です。

```dotenv
OPENAI_API_KEY=ここに自分のAPIキー
OPENAI_MODEL=gpt-6-luna
PORT=4317
APP_ACCESS_TOKEN=32文字以上の十分にランダムな値
```

`.env.local` はGit管理対象外です。モデルは環境変数で変更できます。ChatGPTの画面や契約ではなく、OpenAI APIの利用枠を使います。

## 使い方

1. アプリの「↗ 返信を考える」リンクをブラウザーのブックマークバーにドラッグします。難しい場合は「コードをコピー」で取得し、ブックマークのURL欄に貼り付けます。
2. Xで対象ポストの詳細ページ（`/ユーザー名/status/ID`）を開きます。長文は全文を表示します。
3. 登録したブックマークレットを実行します。アプリが別タブで開き、本文と本文中のリンクを取り込みます。ページのフラグメントで受け渡し、取り込み後にURLから取り除きます。
4. 本文・リンク先・返信の雰囲気を確認して「返信案をつくる」を押します。手動でURLと本文を入力することもできます。
5. 3案から選んで編集し、下書きを保存するか「Xで返信する」で返信画面へ進みます。投稿操作はX上で自分で行います。
6. 投稿後、アプリに戻って「投稿済みとして記録」を押します。その記録が、次回の同じ相手への返信に使われます。

ブックマークレットでアプリが開かない場合はポップアップ設定を確認し、手動入力を利用してください。XのDOM変更やブラウザーの制限により、ブックマークレットの調整が必要になる場合があります。

## 保存と一覧

- 保存先はアプリを開いたブラウザーのlocalStorageです。サーバーに履歴DBは作りません。
- 元投稿、選んで編集した返信、返信案、リンク取得結果、下書き／投稿済み状態、更新日時を保存します。同じポストの保存は既存の記録を更新します。
- リンク先の取得本文は生成中に利用し、履歴には保存しません。履歴にはURL・タイトル・取得状態が残ります。
- 初期上限は相手ごと20件、全体500件。設定でそれぞれ1〜100件、1〜1000件に変更できます。更新日時が古い記録から削除します。
- 次回の文脈は同じ相手への投稿済み返信の最新3件。1〜3件に変更できます。下書き・別の相手・現在のポストは除外します。以前の設定が4件以上でも参照は3件までとし、保存済みの履歴は削除しません。
- 相手の識別は大文字小文字を区別しないXユーザー名です。相手がユーザー名を変えた場合、自動では関連付けません。
- 履歴画面で相手・本文・返信の検索、相手と状態の絞り込み、編集、削除ができます。
- 別タブの保存はWeb Locksで直列化し、保存直前に最新の履歴を読み直します。同じポストへの編集は後の保存が優先されます。
- 容量不足や保存拒否は画面で通知します。ブラウザーの容量制限により、設定件数より早く容量不足になる場合があります。破損したデータは自動上書きしません。
- バックアップは「設定・はじめかた」→「バックアップ・復元」→「バックアップJSONをダウンロード」で取得します。履歴画面にも同じボタンがあります。ファイル名は `x-replies-日付.json`、保存先は通常「ダウンロード」フォルダーです。見つからない場合はブラウザーのダウンロード一覧を確認してください。復元は同じ設定画面でファイルを選択します。既存データを置き換えるため、ブラウザーデータを削除する前やVercelへ移す前にダウンロードしてください。

## 内容確認の範囲

リンク先は公開HTTP/HTTPSページのテキストを最大5件取得します。1ページ最大1.5MB、抽出本文は最大12,000文字、転送は4回までです。節約のためAIへ渡す本文は各リンク先頭1,000文字までとし、画面にも実際に渡した範囲を表示します。外部ページは命令ではなく参考資料として扱うようモデルに指示しています。

ログイン・JavaScript実行・取得拒否・非HTML等によって読めないページは「未確認」としてAIと画面に伝えます。取得できたHTMLがログイン案内やアクセス拒否画面の場合もあるため、画面の「AIに渡したテキストを見る」で確認できます。画像・動画・引用ポストの内容は解析しません。ハッシュタグの意味は取り込んだ本文とモデルの理解に基づき、X上での追加検索はしません。

OpenAIには生成時に元投稿、取得したリンク本文、本人の設定、対象の返信履歴を送ります。Responses APIに `store: false` を指定しています。これはこのアプリ側でAPIのレスポンス保存を要求しない設定で、サービス側のデータ取扱い全般を保証するものではありません。

APIは公式の[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)に沿って3案をJSONで取得します。初期モデルは[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)です。

返信は利用者本人から元投稿者への発言として生成します。本文中の呼びかけを投稿者名と取り違えないように指示し、相手の名前が確実でない場合は宛名を省きます。生成指示の更新時はキャッシュの世代を変更し、古い案の自動再利用を避けます。保存済みの返信履歴は書き換えません。

## API費用の節約

「セルフレスバ：冷笑系エアリプ案をつくる」は、取り込んだ元ポストの内容に対する短い皮肉コメントを3案生成します。通常の返信とは別欄で選択・編集し、「Xでエアリプする」で通常の投稿画面を開きます。返信先ID・元ポストURLは付けず、実際の投稿はX側で行います。エアリプは相手との会話として扱わないため、過去の返信履歴を生成に使わず、この編集欄の内容も返信履歴に保存しません。生成結果の24時間キャッシュは通常返信と区別して保存します。

- GPT-6 Lunaを推論なし（`reasoning.effort: none`）で使用し、1回の出力は最大1,200トークンに制限します。3つの返信案は維持し、各案120文字以内を指示します。
- 送信する元投稿は先頭3,500文字、過去の返信は最大3件（各元投稿400文字・返信240文字）、リンク本文は各1,000文字、本人の希望は先頭500文字までです。元データの保存内容は削りません。長文を短縮した場合は画面で知らせます。
- 同じ本文・設定・返信履歴・モデル・生成仕様なら、生成結果をlocalStorageから24時間再利用します。最大50件で、通常の返信履歴とは別に保存します。同じブラウザーの複数タブで同じ生成を実行した場合はWeb Locksで直列化します。
- 再利用時にはOpenAI APIを呼びません。モデル設定とログイン状態の確認はサーバーへ問い合わせます。「別の案を再生成（API利用）」は明示的に生成し直します。リンク先の内容が変わった場合もこのボタンを使います。
- 失敗時の自動再試行・高額モデルへの自動切り替えは行いません。生成失敗はキャッシュしません。キャッシュ保存に失敗した場合は画面で通知します。
- キャッシュは同じブラウザー・Origin内に限られ、ブラウザーデータ削除、期限切れ、別端末、明示的再生成、条件変更では追加のAPI利用が発生します。キャッシュ自体も暗号化されません。バックアップ対象は従来どおり保存済みの返信履歴です。

2026-10-21の公式単価はGPT-6 Lunaが入力$0.10・出力$0.50/100万トークンです。従来の[GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini)の入力$0.25・出力$2.00に対して、単価はそれぞれ60%・75%低くなります。実際の請求額は入力長・出力長・再利用率で変わります。短い架空ポスト1件の比較では、GPT-6 Luna（推論なし）が入力98・出力53トークン、GPT-5 nano（minimal）が入力98・出力105トークンでした。この1例での概算はそれぞれ$0.0000363と$0.0000469で、品質や費用の一般的な保証ではありません。

## サーバー認証とVercel

- `src/bookmarklet.js`: Xの画面から対象ポストを抽出
- `src/core.js`: データ整形、保存上限、返信コンテキスト
- `src/main.js` / `src/style.css` / `index.html`: アプリ画面
- `server/links.js`: 公開リンクの取得と本文抽出。DNS解決先を固定し、プライベートIPと転送先を検査
- `server/llm.js`: OpenAI APIへの生成要求
- `server/index.js`: ローカルHTTPサーバー
- `server/handler.js`: ローカルとVercel共通の認証・ルーティング
- `server/auth.js`: パスワード照合、署名Cookie、試行制限
- `api/handler.js`: Vercel Node.js Functionの入口
- `auth/`: 公開ログイン画面
- `src/session.js`: ログアウト・別タブ通知・セッション確認

既存のHTML/JavaScript構成を維持し、Vercelではすべてのアプリ画面・資材・APIを同じNode.js Functionで配信します。`dist` に置くのは検索除外用の `robots.txt` だけです。ビルド時にもアプリファイルが公開ディレクトリへ入っていないことを検査します。

Vercelのプロジェクト設定 → Environment Variables → Production に `APP_ACCESS_TOKEN` と `OPENAI_API_KEY` をSecretとして設定します。ブラウザーに渡す変数にはしません。追加ドメインを使う場合は `APP_ORIGIN=https://実際のドメイン` を設定します。Vercelのシステム変数による本番ドメイン・デプロイURLも許可対象です。`OPENAI_MODEL` は任意で、未設定時は `gpt-6-luna` です。

`APP_ACCESS_TOKEN` は32〜512文字の空白を含まないASCIIで、少なくとも12種類の文字を必要とします。この形式検査は乱数性の保証ではないため、パスワードマネージャーや暗号学的乱数生成を使ってください。APIキーをログインパスワードに流用しないでください。

認証の仕様:

- パスワードはサーバーでハッシュ化後、定時間比較します。認証設定が不正・未設定の場合は503で拒否します。
- CookieはHMAC-SHA256署名付きで30日間。本番は `__Host-xps_session`、`HttpOnly; Secure; SameSite=Strict; Path=/` を付け、Domainを指定しません。HTTPのローカル環境だけ別名のSecureなしCookieを使います。
- Cookie署名は現在のパスワードに結び付くため、パスワード変更を反映したサーバーは以前のCookieを拒否します。パスワードやAPIキーはCookieの中にも入れません。
- 各保護API・画面・JS/CSSの配信時に署名と期限を検証します。画面をJavaScriptで隠すだけの認証ではありません。
- ログイン・ログアウト・返信生成のPOSTで、要求のOriginを実際の許可されたサイトOriginと完全一致で検証します。
- ログイン試行はIPごとに15分間5回。成功を含む試行数です。**メモリー内の制限なので、Vercelの別インスタンス間では厳密に共有されず、再起動でもリセットされます。** 分散環境全体の厳密な制限が必要になった場合は共有ストアかVercel Firewallに移行します。同時生成制限もインスタンス単位です。
- 認証画面・保護対象・エラー応答に `Cache-Control: private, no-store` とCDN向け `no-store`、`Vary: Cookie, Origin` を付けます。CSPを維持し、form-action、フレーム拒否、HTTPS本番のHSTSを追加します。
- ログアウトはCookieを削除し、表示中のアプリを破棄します。BroadcastChannelと保存データとは別の通知キーで同一Originの別タブにも通知します。通知キーにはランダムなイベントIDだけを入れ、認証情報は保存しません。タブ復帰時にもサーバーで認証状態を再確認します。
- SameSite=Strictにより外部遷移時にCookieが付かなくても、ログイン画面の同一Origin要求でセッションを再確認し、有効なら再入力せずアプリへ移ります。取り込みデータのURLフラグメントはログインをまたいで保持します。
- ログアウトしても履歴・設定を消しません。**localStorageの保存データ自体はこの認証では暗号化されません。** 同じ端末・ブラウザープロファイルを操作できる人からの保護にはなりません。

パスワード変更はVercelの `APP_ACCESS_TOKEN` を新しい乱数値に置き換え、Productionへ再デプロイします。環境変数の変更だけでは稼働中デプロイに反映されません。古いデプロイは当時の設定を保持するため、古いデプロイURLへのアクセス保護を維持し、必要なら削除してください。認証を導入する前のバージョンへ公開ロールバックしないでください。ローカルのパスワードも変える場合は `.env.local` を更新します。

通常の反映はテスト → 本番ビルド → Gitコミット・mainへのpush → Vercelの本番デプロイ → 実通信確認の順です。CLIによるデプロイとGit自動デプロイは別に確認します。`vercel.json` と[公式Node.js Functions資料](https://vercel.com/docs/functions/runtimes/node-js)、[公式キャッシュ制御資料](https://vercel.com/docs/caching/cache-control-headers)を参照してください。

localStorageのデータは移行先URLへ自動では移りません。ローカルでJSONバックアップを書き出し、公開アプリのログイン後に復元し、ブックマークレットを新URLで登録し直してください。保存キーとデータ形式は変更していません。

自動テスト、ローカルHTTP応答、公開リンクの取得を確認しています。2026-10-21に `.env.local` のキー認識と、架空の短い投稿に対する実APIでの3案生成も確認しました。実際のX画面からの取り込みと描画レイアウトは、操作可能なブラウザーがないため未検証です。
